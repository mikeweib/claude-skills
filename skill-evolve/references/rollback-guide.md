# 回滚操作指南

## 备份存储结构

每次进化应用变更前，skill-evolve 自动创建备份快照：

```
skill-evolve/evolution-log/<skill-name>/backups/<YYYY-MM-DD-<slug>>/
├── <skill>_SKILL.md                     # SKILL.md 的完整原文
├── <skill>_references_<file>.md          # 其他受影响文件的完整原文
└── ...
```

**备份文件命名规则：** 将目标文件的仓库相对路径中的 `/` 替换为 `_`：
- `prd-review/SKILL.md` → `prd-review_SKILL.md`
- `prd-review/references/review-checklist.md` → `prd-review_references_review-checklist.md`

## 回滚决策树

```
用户: "回滚 <skill-name>"
│
├─ 有进化记录？
│  ├─ 否 → 提示 "暂无进化记录，无需回滚"
│  └─ 是 → 列出可回滚记录
│     │
│     ├─ 选中记录有备份？
│     │  ├─ 否 → 提示手动操作，展示进化记录中的变更详情
│     │  └─ 是 → 展示回滚 diff 预览
│     │     │
│     │     ├─ 用户指定日期？
│     │     │  ├─ 精确匹配 → 直接展示该日期的回滚预览
│     │     │  ├─ 近似匹配 → 提示最接近日期，让用户确认
│     │     │  └─ 无匹配 → 提示无此日期记录
│     │     │
│     │     ├─ 多记录堆叠？
│     │     │  └─ 警告 "回滚将影响 N 条后续进化记录"
│     │     │
│     │     └─ 用户确认 → 执行回滚
│     │        ├─ 从备份恢复文件
│     │        ├─ 创建回滚记录
│     │        ├─ 更新原进化记录状态
│     │        └─ 询问反馈处理方式
```

## 回滚后的反馈处理策略

| 选项 | 行为 | 适用场景 |
|------|------|---------|
| **重新分析** | 原反馈标记为未处理，下次进化时重新评估 | 进化方向正确但实现有问题 |
| **保留已处理** | 原反馈状态不变 | 已通过其他方式解决 |
| **标记无效** | 原反馈标记为无效，不再触发进化建议 | 反馈本身有误 |

## 安全检查清单

回滚执行前必须确认：

- [ ] 备份目录存在且包含所有受影响文件的备份
- [ ] 备份文件内容非空（行数 > 0）
- [ ] 备份文件包含对应目标文件的关键章节标识（如 SKILL.md 的 `---` frontmatter）
- [ ] 当前文件内容已读取（用于 diff 对比）
- [ ] 用户已查看回滚 diff 预览
- [ ] 用户显式确认回滚

## 回滚记录 vs 进化记录

| 维度 | 进化记录 | 回滚记录 |
|------|---------|---------|
| 文件名 | `YYYY-MM-DD-<slug>.md` | `YYYY-MM-DD-rollback-<slug>.md` |
| 状态 | ✅ 已应用 / ❌ 已拒绝 / 🔄 已回滚 | 🔄 已回滚 |
| 触发来源 | feedback | 用户主动要求 |
| 影响文件 | 记录了变更 diff | 记录了恢复自哪个备份 |
| 关联 | 指向触发反馈 | 指向被回滚的进化记录 |

## 回滚后再次回滚（回滚的回滚 = 恢复）

如果回滚后用户发现回滚错误，可以对回滚记录再次执行回滚：

1. 回滚记录的备份 = 回滚前的状态（即回滚前的文件内容）
2. 对回滚记录执行回滚 → 恢复到回滚前的状态（即进化后的状态）
3. 本质上形成版本链：`进化前 → 进化后 → 回滚后 → 再次回滚（恢复进化后）`

这就是为什么备份快照永远不删除——它支持任意方向的版本切换。
